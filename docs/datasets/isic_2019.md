# ISIC 2019 (`isic_2019`)

The ISIC 2019 Challenge dermoscopy release, downloaded from the [ISIC Archive](https://www.isic-archive.com/). Licensing is per image and is kept in the `copyright_license` column.

## Bronze metadata columns

`bronze.isic_2019_source_metadata` keeps the source metadata as published, plus the standard lineage columns described in the [data contract](../data_contract.md#bronzedataset_source_metadata). All source columns are strings.

| Columns | Notes |
|---|---|
| `attribution`, `copyright_license` | Attribution and license, per image |
| `age_approx`, `sex` | Patient demographics |
| `anatom_site_1` … `anatom_site_5`, `anatom_site_special` | Anatomic site hierarchy (5 levels) |
| `diagnosis_1` … `diagnosis_5`, `diagnosis_confirm_type` | Diagnosis hierarchy (5 levels) and how it was confirmed |
| `clin_size_long_diam_mm` | Clinical lesion size |
| `concomitant_biopsy`, `melanocytic`, `dermoscopic_type`, `image_type` | Source flags |
| `family_hx_mm`, `personal_hx_mm` | Family and personal melanoma history |
| `lesion_id`, `patient_id` | Used for leakage grouping |

## Labels

The shared `normalize_diagnosis_labels` reads `diagnosis_1`, `diagnosis_2` and `diagnosis_3`, as set by `diagnosis_input_columns` in the config:

- `malignancy` comes from `diagnosis_1`, mapped onto `benign`, `malignant` or `indeterminate`.
- `specific_diagnosis` is the deepest of those three levels that has a value.

A row where neither resolves is rejected. `diagnosis_4` and `diagnosis_5` stay in Bronze but don't feed the labels.

## Leakage grouping

Images sharing identical bytes, a `lesion_id` or a `patient_id`, directly or through a chain of such links, form one group, so all images of a patient stay together even across their different lesions.

## Image validation

Uses the [default thresholds](README.md#default-image-validation-thresholds) unchanged. A near-uniform-color check was tried and removed, because valid images can have low pixel variance, for example a lot of dark background.
